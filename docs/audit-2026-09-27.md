# Аудит Telegram iOS: проверенные изменения и границы покрытия

Дата: 27 сентября 2026. Ветка: `arena/01a070bb-telegram-ios`.
Исходное состояние этого прохода: `516ae93b01`.

## 1. Результат и статус

Это **частичный инженерный аудит с исправлениями**, а не подтверждение идеального состояния приложения.
Приоритет отдан сохранности пароля архива, корректности загрузок, общим компонентам интерфейса,
VoiceOver и работе истории сохранённых сообщений. Специальный раздел «подборки» исключён по уточнению пользователя.

Первый набор кода: `28db40c15d`. Его regression job в
[CI](https://github.com/decoder-dev/Telegram-iOS/actions/runs/36308297359) прошёл.
Полная iOS-сборка на момент записи ещё не подтверждена. Исправление миграции и его отдельный тест добавлены следующим набором.
Статус проверки окончательной версии нужно брать из последнего CI, а не переносить с предыдущего SHA.

Построчный аудит всего репозитория **не выполнен**. В
[машиночитаемом реестре покрытия](audit-2026-09-27-coverage.json) перечислены проверенные участки,
файлы, использованные только для карты архитектуры, и остальные исходники. Поиск совпадений не считается чтением файла.
Документ `ui-audit.md` описывает предыдущие проходы; его широкие утверждения здесь не используются как доказательство.

## 4. Карточки изменений: причина, реализация, риск, проверка

### A01 — сохранность старого пароля

- **Категория / компонент:** Security, migration; `archiveSettingsController`.
- **Проблема / воздействие:** после ошибки Keychain можно потерять единственный хеш; если protection mirror также отсутствует, следующий resolve может считать архив незащищённым.
- **Причина:** `archiveIsPasswordProtected` остаётся fail-closed при legacy credential, но экран воспринимал этот результат как подтверждение переноса и безусловно очищал legacy.
- **Рекомендация / реализация:** удалять старое значение только при `ArchivePasswordKeychain.hasPassword`; одновременно выставить `isPasswordConfigured(true)` для notification redaction.
- **Риск регрессии:** низкий; при отказе миграции старый хеш теперь сохраняется. При недоступном Keychain доступ может оставаться заблокированным — это предпочтительнее потери защиты.
- **Проверка:** `Tests/ArchiveLock/migration.py`: Keychain недоступен/доступен × mirror false/true; при отказе legacy неизменен, при успехе legacy удалён и mirror=true. На устройстве дополнительно проверить миграцию старого аккаунта и отказ доступа к Keychain.

### A02 — не сообщать ложный успех

- **Категория / компонент:** Reliability/security; `presentArchivePasswordAlert`, `setArchivePassword`, `changeArchivePassword`, `removeArchivePassword`, `ArchivePasswordKeychain.clear`.
- **Проблема / воздействие:** пользователь видел включение/изменение/снятие защиты при неуспешной мутации credential.
- **Причина:** результаты `store`/`clear` отбрасывались; подтверждение всегда вызывало onSuccess.
- **Рекомендация / реализация:** capture callback возвращает Bool; при ошибке сохранения повторный ввод с сообщением, без success. При отказе удаления — completion(false), уведомление об ошибке, mirror не меняется. Failure counter не очищается после неуспешного удаления.
- **Риск регрессии:** средний: изменён обработчик настройки/ротации пароля. Все вызовы capturePassword найдены и обновлены.
- **Проверка:** `password_flow.py` выполняет реальную функцию показа пароля с заменой только UIKit/Keychain boundaries: отказ, повторная попытка, успех, несовпадение, отмена. Реальный Keychain/Security OSStatus на iPhone не инжектировался.

### A03 — освобождение диалогов

- **Категория / компонент:** Memory/lifecycle; action handlers первого и подтверждающего UIAlertController.
- **Проблема / воздействие:** dismiss не разрывает цепь владения alert/action, могут оставаться поля пароля и захваченный контекст.
- **Причина:** сильный capture самого владельца UIAlertAction.
- **Рекомендация / реализация:** `[weak alert]` и `[weak confirm]`, guard перед чтением поля.
- **Риск регрессии:** низкий; UIKit удерживает показанный alert на время действия. Если alert уже уничтожен, callback ничего не делает.
- **Проверка:** weak references освобождаются после submit; 20 повторов несовпадение/отмена. Это тест ownership на fixtures, **не измерение RAM устройства**.

### A04 — размер отвергнутого EOF

- **Категория / компонент:** Correctness/cache; `commitPendingReadyPart`.
- **Проблема / воздействие:** при knownSize=nil отклонённый короткий ответ всё ещё публиковал меньший resultingSize; потребитель мог усечь представление медиаресурса.
- **Причина:** проверка `downloadedUpperBound` ограждала только присваивание knownSize, но не событие `resourceSizeUpdated`.
- **Рекомендация / реализация:** лог и событие размера перенесены внутрь ветки принятия EOF.
- **Риск регрессии:** низкий для размера; обработка повторной загрузки отклонённого диапазона не переработана и остаётся отдельным вопросом.
- **Проверка:** все перестановки full/partial/empty EOF, точная граница, ложный EOF после более поздних полученных байтов при известном и неизвестном размере. Проверяется отсутствие события, а не только внутреннее поле.

### A05 — safe area

- **Категория / компоненты:** Layout/rotation; `asyncLayout` обоих многострочных компонентов.
- **Проблема / воздействие:** при разных left/right insets левый край и перенос текста не соответствуют доступной области.
- **Причина:** `params.rightInset` использовался для leftInset; текстовая строка вычитала `leftInset * 2`.
- **Рекомендация / реализация:** независимые отступы; ширина неотрицательна. Поиск того же выражения выполнен по ItemListUI; похожее выражение в ItemListTextItem имеет другую формулу и автоматически не менялось.
- **Риск регрессии:** средний для общих строк; симметричный portrait layout сохраняет прежнюю ширину.
- **Проверка:** landscape в обе стороны, iPad split view, VLESS, длинная история и XXL. Screenshot comparison пока отсутствует.

### A06 — реальная доступность действия

- **Категория / компонент:** Accessibility/touch; ItemListMultilineTextItemNode.
- **Проблема / воздействие:** AccessibilityAreaNode возвращает false без activate handler, хотя визуально строка нажимается.
- **Причина:** общий multiline компонент задавал только accessibilityLabel.
- **Рекомендация / реализация:** handler с weak self вызывает **текущее** item.action; `.button` для action, `.staticText` иначе; actionable row не ниже 44 pt.
- **Риск регрессии:** средний, компонент общий. Long-press и inline links этим изменением не переосмыслены.
- **Проверка:** VoiceOver double-tap на вложении, строка без вложения, переиспользование item с другим action, переключение темы/шрифта. Статические VoiceOver tests не доказывают эти сценарии.

### A07 — история без синхронного чтения на UI queue

- **Категория / компонент:** Performance/concurrency; messageSavingHistoryController, цепь store read → entries → list state.
- **Проблема / воздействие:** открытие/refresh списка может ждать JSON load, lock, фильтрацию и сортировку до 5000 snapshots на main.
- **Причина:** combineLatest доставлялся на main перед map; reconciliation выбирал записи до dispatch в background.
- **Рекомендация / реализация:** подготовка состояния на своей serial Queue, `deliverOnMainQueue` после map; reconciliation читает список уже в utility block.
- **Риск регрессии:** средний: асинхронная первая выдача, возможна очередь обновлений при частых mutations. Coalescing и cancellation текущего reconciliation не добавлялись без отдельной модели.
- **Проверка:** открыть пустую/5000-record историю, обновлять store при прокрутке, закрыть экран во время reconciliation, сравнить main-thread trace и latency. Замеры ещё не получены.

### A08 — честные действия и язык даты

- **Категория / компонент:** UX/localization; MessageSavingHistoryEntry.item.
- **Проблема / воздействие:** строка без файла реагировала как кнопка без результата; язык даты не следовал Telegram.
- **Причина:** непустая closure даже без mediaPath/file; DateFormatter без locale.
- **Рекомендация / реализация:** action=nil без доступного файла, повторная проверка файла при нажатии; locale=baseLanguageCode.
- **Риск регрессии:** низкий; исчезновение файла между показом и нажатием пока не сопровождается отдельной ошибкой. Формат времени 12/24 требует отдельной сверки.
- **Проверка:** файл есть/отсутствует/появился после refresh/удалён после показа; разные языки приложения и устройства.

### A09 — единый fallback Extras

- **Категория / компонент:** Localization/code duplication; ForkExtrasLocalizedString.languageCode.
- **Проблема / воздействие:** например, при немецком Telegram и русском iOS Extras мог быть русским, тогда как остальные fork menus были английскими.
- **Причина:** второй самостоятельный поиск Locale после неподдерживаемого appLanguage.
- **Рекомендация / реализация:** использовать существующий ForkPresentationLanguage; сохранить уже принятый fallback ru/uk/be → ru, прочие → en.
- **Риск регрессии:** низкий; новые переводы не добавляются, язык устройства больше не перебивает явный язык приложения.
- **Проверка:** native MenuPresentation runner компилирует production enum и проверяет ru/en/de/uk вместе с Archive/VLESS.

## 5. UI/UX, темы и дизайн-система

Не вводилась новая палитра поверх Telegram. Использовать существующие роли:
`itemPrimaryTextColor`, `itemSecondaryTextColor`, `itemAccentColor`, `itemDestructiveColor`,
background/separator из той же группы theme.list; размеры из presentationData.fontSize.
Safe-area insets складывать отдельно с базовыми отступами; общие controls менять в ItemListUI.
44 pt — минимум для action row, а не основание увеличить все декоративные элементы.

Не заменять все числовые отступы общей сеткой без screenshots: компоненты имеют разные baseline, safe area и grouped/plain contracts.
Не перекрашивать все `.white`/`.black` автоматически: часть цветов служит масками, измерительным текстом или предпросмотром темы.
Предыдущая гипотеза про неверные цвета кнопок удаления отклонена: iconless pill использует iconColor; лишние изменения не внесены.

Полный dark-mode pass, уменьшение анимаций, RTL, navigation transitions, thumbnails/skeletons и контраст пользовательских тем **не проверены на экране**.
Карточки/подборки специально не перепроектировались по уточнению пользователя.

## 9. Что не проверено и почему

Полный список исходников — в coverage JSON (`notInspected`). Карта архитектуры не означает аудит реализации.
Причины: размер дерева и необходимость отдельных воспроизводимых сценариев; доступ к Windows не даёт iOS Simulator/Instruments.
Сторонние gitlinks, Xray binary framework, FFmpeg/WebRTC/codecs, generated API и другие vendored материалы не проходили самостоятельную проверку безопасности.
Остальные core/storage/transport методы, chat/media/story/call screens, авторизация/deep links, покупка/платежи,

Это явный вариант B из задания, а не утверждение о завершённом сплошном аудите.

## 10. Приоритетный дальнейший план

1. Подтвердить последнюю полную сборку и fault-injection тест миграции. До этого не маркировать IPA проверенным релизом.
2. На устройстве: setup/change/remove password с отказами, cold start старого аккаунта, 10 taps, Saved Messages, смена аккаунта и background.
3. Проверить shared multiline components: VoiceOver, XXL, landscape в обе стороны, split view, темы, RTL; снять screenshots.
4. Записать сеть/PTS и Instruments на одинаковом workload, локализовать R01–R03; не настраивать кэши по одному пиковому числу.
5. Разобрать download retry R04 и password presentation R07 отдельными конечными автоматами и regression tests.
6. По coverage ledger продолжить chat list/history → media/gallery → notifications/calls → auth/deep links → остальные settings → extensions и vendored boundaries.

Окончательный критерий качества — воспроизводимый сценарий и проверка результата каждого изменения, а не объём diff или отсутствие ошибок компилятора.
